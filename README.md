# 표 OCR 인쇄 도우미 (Electron)

사진 속 표(영어/한글 혼합)를 OCR(PaddleOCR, 기본값) 또는 VLM(Vision-Language Model)으로 인식해서,
영어 전용 시험지 / 한글 전용 시험지(각각 오른쪽에 답 쓰는 빈 칸 포함, 세로 A4 1페이지 1표 또는 가로 A4 1페이지 2표)를 만들어
인쇄하거나 PDF로 저장하는 Windows용 Electron 앱입니다.

## 실행 방법

```
npm install
npm start
```

## 지원하는 사진 형태

이 앱은 실제로 아래와 같은 단어표 사진으로 테스트했습니다 (`samples/` 폴더).

| ![샘플 1](samples/sample-word-table-1.jpg) | ![샘플 2](samples/sample-word-table-2.jpg) |
| --- | --- |

- 기본 구조는 왼쪽부터 **순번(번호) → 영어 → 한글 뜻** 순서의 표입니다.
- 위 샘플처럼 **한 페이지에 이 3열 블록이 좌우로 2개 나란히 붙어 있는 형태**(예: 1~20번은 왼쪽 블록, 21~40번은 오른쪽 블록)도 지원합니다 — 인식 시 영어/한글 열이 각각 2개씩 잡히는데, 인쇄용 표에서는 각 영어(또는 한글) 열마다 답 쓰는 빈 칸이 바로 옆에 따로 붙어서 나옵니다.
- 순번 열은 인식은 되지만 인쇄/PDF 출력에는 포함되지 않습니다(필요 없는 정보라 항상 제외).
- 사진 한 장에 위 구조와 많이 다른 표(예: 열 순서가 다르거나 3열 이상의 다른 정보가 섞인 표)는 인식 정확도가 떨어질 수 있습니다.

## 표 인식 방식

설정(⚙)에서 셋 중 하나를 선택할 수 있습니다. **기본값은 PaddleOCR**입니다.

- **PaddleOCR (로컬 OCR, 기본값)**: 이 PC의 Python에 설치된 PaddleOCR(PP-Structure)로 표를 인식합니다. 오프라인/무료로 동작하며 API 키가 필요 없습니다.
  - 사전 준비: `pip install paddlepaddle "paddleocr[doc-parser]"`
    - **Python 3.9~3.13**이 필요합니다. PaddlePaddle은 아직 3.14용 휠을 제공하지 않아 3.14에서는 설치가 실패합니다.
    - 표 인식(PP-StructureV3)에는 `doc-parser` extra가 필요합니다. `pip install paddleocr`만 하면 `PP-StructureV3 requires additional dependencies` 오류가 납니다.
    - Python이 PATH에 없거나 여러 버전이 설치돼 있으면 설정에서 Python 실행 파일 경로를 직접 지정할 수 있습니다.
  - 최초 인식 시 모델 파일(`%USERPROFILE%\.paddlex\official_models`)을 자동 다운로드하므로 몇 분 걸릴 수 있습니다. 이후에는 캐시를 재사용합니다.
  - OCR은 표의 글자만 읽으므로 각 열의 영어/한글 구분은 앱이 글자 비율로 자동 판별합니다(2단계에서 확인·수정 가능).
  - **글자가 작은 저해상도 사진은 정확도가 크게 떨어집니다.** 앱이 긴 변 2200px까지(최대 3배) 자동으로 확대해 보정하지만, 애초에 큼직하게 찍은 사진일수록 결과가 좋습니다.
    - `samples/`의 653×736 이미지 기준: 확대 없이는 영어·한글 각 40개 중 약 27~28개만 정확했고, 확대를 켜면 각 37개, 여기에 텍스트라인 방향 분류기까지 끄면 **영어 38~39개 / 한글 39~40개**(약 95~98%)가 정확해졌습니다.
  - **테두리(괘선)가 없는 표는 인식 자체가 실패할 수 있습니다.** 표 검출이 시각적 격자에 의존하기 때문입니다(아래 벤치마크에서 테두리 없는 31장 중 10장 실패, 괘선이 있는 69장은 실패 0).
  - 인식 결과가 완벽하지 않을 수 있으니 2단계(결과 확인/수정)에서 훑어보고 고치는 것을 권장합니다.
- **OpenAI (GPT-4o Vision, 클라우드)**: API 키 필요, 인터넷 연결 필요, 인식 정확도가 가장 높음
- **Ollama (로컬 모델)**: PC에 설치된 Ollama의 vision 모델(예: `qwen2.5-vl`, `llama3.2-vision`, `qwen3-vl` 등) 사용, 오프라인/무료 가능. Ollama 서버가 꺼져 있으면 앱이 자동으로 실행을 시도합니다.

### 어떤 방식을 쓸까 (벤치마크 결과)

영어·한글이 섞인 단어표 이미지 100장(단어쌍 1913개)으로 다섯 가지 방식을 비교했습니다. 전체 결과와 측정 방법은 **[bench/BENCHMARK.md](bench/BENCHMARK.md)** 를 보세요.

| 방식 | 단어쌍 정확도 | 장당 소요 | 특징 |
| --- | --- | --- | --- |
| OpenAI gpt-4o | **99.5%** | 3.1초 | 가장 정확하고 빠름. 100장에 약 $0.5, 인터넷 필요 |
| Ollama qwen2.5vl (로컬 VLM) | 91.4% | 4.7초 | 오프라인·무료인데 PaddleOCR보다 정확하고 빠름 (GPU 기준) |
| PaddleOCR (현재 기본값) | 80.1% | 29.2초 | 오프라인·무료. 테두리 없는 표에서 검출 실패 |
| Ollama qwen3-vl:8b (로컬 VLM) | 77.8% | 45.2초 | 최신 모델이지만 유효한 JSON을 못 내는 경우가 17% |
| Tesseract | 54.2% | 0.8초 | 압도적으로 빠르지만 한글이 58.7%로 약함 |

- **단어쌍 정확도**는 영어와 한글이 모두 정확히 읽히고 *같은 행*에 들어간 비율입니다. 행이 밀려 다른 단어의 뜻이 짝지어지면 시험지로 못 쓰기 때문에 이 기준을 씁니다.
- 정확도가 중요하면 OpenAI를, 오프라인이어야 하고 GPU가 있다면 Ollama(`qwen2.5vl`)를 권합니다. GPU가 없다면 로컬 VLM이 크게 느려지므로 PaddleOCR이 여전히 합리적입니다.
- `bench/` 폴더의 스크립트로 직접 재현할 수 있습니다(`generate.py` → `run_bench.py <엔진>` → `score.py`).

위 표는 **표 인식** 성능입니다. 실제 연구 논문 PDF 100건으로 **페이지 전체 텍스트 전사** 성능을 따로 측정한 결과는 **[bench-papers/BENCHMARK.md](bench-papers/BENCHMARK.md)** 에 있습니다. 그쪽에서는 순위가 달라집니다 — 로컬 VLM(`qwen2.5vl`)이 CER 10.9%로 1위이고, OpenAI gpt-4o는 **100페이지 중 51페이지를 전사 거부**했으며, PaddleOCR은 글자 인식은 가장 정확한데(단어 F1 94.0%) 2단 조판에서 읽는 순서가 깨져 CER이 47.8%로 나빠집니다.

## 사용 흐름

1. **업로드 & 인식**: 표가 있는 사진을 드래그하거나 클릭해서 선택(**여러 장 동시 선택 가능**) → "표 인식 시작" 클릭
   - 기본 인식 방식은 PaddleOCR(로컬)이며, 필요하면 우측 상단 "⚙ 설정"에서 인식 방식(PaddleOCR/OpenAI/Ollama)과 API 키 또는 로컬 모델 정보를 변경할 수 있습니다.
   - 인식 중에는 진행률 표시줄이 단계별로 표시됩니다(여러 장이면 진행 중인 파일 번호도 함께 표시).
2. **결과 확인/수정**: 인식된 표가 편집 가능한 테이블로 나타납니다. 여러 장을 올렸다면 파일별 탭으로 구분됩니다.
   - 각 열이 영어/한글/기타 중 무엇인지 드롭다운으로 확인·수정
   - 셀 텍스트는 클릭해서 직접 수정, 행 삭제 가능
3. **인쇄 미리보기**: 두 가지 탭 제공
   - **영어 전용 (한글 답 쓰기)**: 영어 열만 남기고 오른쪽에 "한글 뜻 쓰기" 빈 칸 추가 — 영어 보고 한글 뜻 맞히기
   - **한글 전용 (영어 답 쓰기)**: 한글 열만 남기고 오른쪽에 "English 쓰기" 빈 칸 추가 — 한글 보고 영어 맞히기
   - **인쇄 형식**을 두 가지 중에서 고를 수 있습니다(두 탭에 함께 적용):
     - `세로 A4 · 한 장에 표 1개` — 기존 방식. 사진 1장이 곧 1페이지입니다.
     - `가로 A4 · 한 장에 표 2개` — 가로 A4에 표를 좌우로 2개 배치합니다. 사진을 2장 올렸다면 두 장이 한 페이지에 들어가고, 1장만 올렸거나 행이 많으면 그 표를 반씩 나눠 좌우에 채웁니다. 표는 페이지 높이에 맞춰 늘어나므로 답 쓰는 칸도 함께 커집니다(한 칸 최대 21행, 넘으면 다음 페이지).
   - 각 탭에서 "🖨 인쇄" 또는 "PDF로 저장" 가능 (용지 방향은 선택한 인쇄 형식에 맞춰 자동 설정)

## Windows 배포용 패키징 (선택)

```
npm run dist
```

`electron-builder`로 NSIS 설치 파일을 생성합니다 (인터넷 연결 필요, 최초 실행 시 빌드 리소스 다운로드).

## 참고

- 설정(API 키 등)은 프로젝트 폴더가 아니라 `%APPDATA%\table-ocr-print\settings.json`에 저장됩니다(git에 포함되지 않음).
- OpenAI를 사용할 경우 API 사용 요금이 발생하며 인터넷 연결이 필요합니다. Ollama(로컬)를 사용하면 오프라인으로도 동작합니다.
